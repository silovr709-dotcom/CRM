# Production-деплой «МойДень» на Timeweb Cloud — разбор и план

Документ отвечает на три вопроса: **что у нас за проект**, **что нужно решить до
деплоя** и **что вам делать руками в панели Timeweb**. Ничего ещё не развёрнуто.

---

## 1. Что мы деплоим (результат проверки репозитория)

| Вопрос | Ответ |
|---|---|
| Стек | Node.js 22 (Express) + React 18/TypeScript (Vite, PWA) |
| Сколько сервисов | **Один**. Сервер отдаёт и API, и собранный сайт, и держит Telegram-бота |
| Нужен ли Docker | **Да.** Готовый `Dockerfile` в корне: собирает фронтенд и запускает сервер |
| Backend | Express, 218 SQL-запросов, вся логика синхронная |
| База данных | **SQLite** (встроенный модуль `node:sqlite`), один файл `organizer.db` |
| Внешние сервисы | Только Telegram Bot API (исходящие запросы, long polling). Платных API нет |
| Нейросети | Не используются: ассистент работает на правилах, интернет ему не нужен |
| Файлы пользователей | Вложения к задачам и проектам — в папку `files/` рядом с базой (до 15 МБ каждый) |
| Порт | `3000` (`EXPOSE 3000` в Dockerfile, переопределяется переменной `PORT`) |
| Проверка состояния | `GET /api/health` — возвращает `{"ok":true}` |
| Фоновые процессы | Telegram-polling, планировщик напоминаний и брифингов, авто-бэкап раз в сутки |
| Масштабирование | **Строго один экземпляр** (SQLite + polling). Реплики включать нельзя |
| Оперативная память | Хватает 1 ГБ; при сборке фронтенда пик ~700 МБ |

### Что уже сделано для production (в этой подготовке)

- 🔒 CORS закрыт: в production кросс-доменные запросы с куками запрещены
  (раньше принимался любой домен — чужой сайт мог действовать от вашего имени).
- 🔒 Защита от перебора пароля: 10 неудачных попыток входа с одного адреса → блок на 15 минут.
- 🔒 Заголовки безопасности + Content-Security-Policy, скрыт `X-Powered-By`.
- 🧯 Аккуратная остановка по SIGTERM: при обновлении версии база корректно
  закрывается (WAL сводится в один файл) — ничего не теряется и не бьётся.
- 💾 Автоматические резервные копии базы раз в сутки (хранится 7 последних) +
  кнопка **«Ещё → Мой аккаунт → Скачать копию»** и эндпоинты `/api/admin/backups`.
- 🩺 `/api/health` проверяет и сервер, и доступность базы; в Dockerfile есть `HEALTHCHECK`.
- 🚀 Кэширование статики: файлы сборки — навсегда, оболочка — без кэша (не «залипнет» старая версия).
- 👤 Контейнер работает не от root, зависимости ставятся `npm ci --omit=dev`.
- 📄 `.env.example` со всеми переменными; секретов в репозитории нет.

## 2. Главный вопрос, который надо решить ДО деплоя

App Platform устроен так: **каждый новый деплой — это новый пустой контейнер**.
Файлы, созданные внутри контейнера, при обновлении версии **исчезают**
(это прямо написано в документации Timeweb). Подключить постоянный диск
к приложению App Platform нельзя — он есть только у облачных серверов.

А у нас всё состояние — это файл SQLite и папка с вложениями.
Значит, «просто задеплоить в App Platform» = терять все задачи при каждом обновлении.
Поэтому выбираем один из трёх вариантов:

### Вариант A. App Platform + S3-хранилище (снимки базы) — «как вы просили»

Приложение живёт в App Platform (автодеплой из GitHub, бесплатный SSL, кнопка «откатить»),
а база и вложения зеркалируются в S3-хранилище Timeweb:
при старте контейнер скачивает последний снимок, дальше сохраняет его
каждые ~5 минут и обязательно при остановке (перед деплоем).

- ✅ Ровно то, что вы хотели: App Platform, автодеплой, ничего не надо настраивать в консоли.
- ✅ Код приложения не переписывается, SQLite остаётся.
- ⚠️ При *аварийном* падении сервера можно потерять последние минуты работы
  (при обычном обновлении — ничего не теряется).
- 🛠 Нужна моя доработка: модуль выгрузки/загрузки в S3 (~полдня работы).
- 💰 App Platform (1 CPU / 1–2 ГБ) + S3 (копейки за гигабайт). Ориентир — несколько сотен ₽/мес.

### Вариант B. App Platform + управляемый PostgreSQL + S3 — «классический production»

Переписываем хранилище с SQLite на PostgreSQL (управляемая база Timeweb с бэкапами
и репликацией), вложения — в S3.

- ✅ Самый «взрослый» вариант: база отдельно, приложение без состояния, ничего не теряется вообще.
- ⚠️ Это **большая переделка**: 218 запросов и весь синхронный код сервисов
  переводятся на асинхронный драйвер. Реально 1–2 дня работы и риск новых багов.
- 💰 Дороже: приложение + управляемая БД (обычно от ~700–1000 ₽/мес) + S3.
- Имеет смысл, если пользователей станет заметно больше трёх.

### Вариант C. Облачный сервер (VDS) + Docker + диск — «дёшево и надёжно для SQLite»

Обычный маленький сервер Timeweb с образом Docker, приложение запускается одной
командой, данные лежат на диске сервера и никуда не деваются.

- ✅ Данные в полной сохранности без всяких S3, всё работает как сейчас.
- ✅ Дешевле всего, и можно включить автоматические бэкапы диска в панели.
- ⚠️ Нет автодеплоя «из коробки» (обновление — одна команда, я подготовлю скрипт),
  и первая настройка идёт через консоль сервера (я дам команды дословно).
- 💰 Ориентир: 1 CPU / 1 ГБ — самый дешёвый тариф облачного сервера.

### Моя рекомендация

Для трёх пользователей и личного органайзера: **A, если важен автодеплой и App
Platform; C, если важнее простота и минимальная цена.**
B — только если планируете расти и подключать ещё людей.

## 3. Что делать вам в панели Timeweb (пошагово)

### Шаг 0. Общее для всех вариантов

1. Зарегистрируйтесь на <https://timeweb.cloud> (вход по телефону/почте, оплата картой РФ).
2. Пополните баланс — хватит 500–1000 ₽ для старта.
3. Зайдите в **Профиль → Безопасность** и включите двухфакторную аутентификацию.
4. Решите, какой домен будет у приложения:
   - бесплатный технический домен Timeweb (вида `myday-xxxx.twc1.net`) — ничего делать не надо;
   - или свой домен — тогда его нужно будет привязать и направить A-записью на приложение.

### Шаг 1 (вариант A). App Platform

1. В панели слева: **App Platform → Создать**.
2. **Репозиторий**: нажмите иконку GitHub → авторизуйтесь → разрешите доступ к
   репозиторию `silovr709-dotcom/CRM` → выберите его.
3. **Ветка**: `main` (перед этим я подготовлю и вмержу изменения в `main`).
4. Оставьте включённой опцию **«Сборка по последнему коммиту»** — тогда любое
   обновление кода само уезжает на сервер.
5. **Фреймворк**: убедитесь, что выбран **Dockerfile** (не Node.js).
6. **Регион**: Россия, Санкт-Петербург или Москва.
7. **Тариф**: минимальный с **2 ГБ RAM** (на 1 ГБ сборка фронтенда может упасть по памяти).
8. **Расширенные настройки**:
   - «Путь до директории проекта» — оставить пустым (Dockerfile в корне);
   - **«Путь проверки состояния»** — вписать `/api/health`;
   - **Переменные** — добавить (значения придумываете вы, мне их присылать не нужно):

     | Имя | Значение |
     |---|---|
     | `ADMIN_LOGIN` | `admin` |
     | `ADMIN_PASSWORD` | ваш надёжный пароль администратора |
     | `TZ` | `Europe/Moscow` |
     | `DATA_DIR` | `/data` |
     | `S3_BUCKET` | имя бакета из шага 2 |
     | `S3_ENDPOINT` | `https://s3.twcstorage.ru` |
     | `S3_ACCESS_KEY` | ключ доступа из шага 2 |
     | `S3_SECRET_KEY` | секретный ключ из шага 2 |

9. Пока **не нажимайте «Запустить деплой»** — сначала я дописываю модуль S3
   (без него данные будут теряться при обновлениях).

### Шаг 2 (вариант A). S3-хранилище

1. В панели: **Хранилище S3 → Создать бакет**.
2. Имя, например `myday-data`, тип — **приватный**.
3. Откройте бакет → **Доступ / Ключи** → создайте пару ключей
   (Access Key и Secret Key). Скопируйте их — они показываются один раз.
4. Эти два ключа вставьте в переменные приложения (шаг 1.8). **Мне их не присылайте.**

### Шаг 1 (вариант C). Облачный сервер

1. **Облачные серверы → Создать**.
2. Образ: **Docker** (в разделе «Приложения» или «Готовые образы»).
3. Тариф: 1 CPU / 1 ГБ / 15 ГБ диска, регион — Россия.
4. Включите **резервное копирование диска** (галочка при создании, стоит копейки).
5. Скопируйте root-пароль/ключ, который панель покажет после создания,
   и IP-адрес сервера. **Пароль мне не присылайте** — он нужен только вам.
6. Дальше я дам 4 команды, которые вы вставите в **Консоль** прямо в панели
   (кнопка «Консоль» на странице сервера) — они скачают код, соберут образ и
   запустят приложение с постоянной папкой для данных.

### Шаг 3. После запуска (любой вариант)

1. Откройте выданный адрес — увидите экран входа.
2. Войдите как `admin` с паролем из переменной `ADMIN_PASSWORD`.
3. **Ещё → Пользователи** — заведите жену и мастера Сергея.
4. **Ещё → Настройки → Telegram** — вставьте токен бота от @BotFather
   (каждый пользователь вставляет свой; токен хранится в базе, в GitHub он не попадает).
5. **Ещё → Мой аккаунт → Скачать копию** — сделайте первую резервную копию
   и сохраните файл у себя. Дальше копии создаются автоматически раз в сутки.
6. На телефоне откройте адрес и нажмите «Установить приложение» / «На экран Домой».

## 4. Что мне нужно от вас

Секреты (пароли, токены, ключи S3, доступы к серверу) **присылать не нужно и нельзя** —
вы вводите их сами в панели Timeweb и в приложении. От вас нужны только решения и факты:

1. **Какой вариант выбираем** — A (App Platform + S3), B (PostgreSQL) или C (сервер с Docker)?
2. **Домен**: бесплатный технический от Timeweb или свой? Если свой — какой именно
   (и где куплен, чтобы я подсказал, какие DNS-записи прописать).
3. **Логин администратора** — оставляем `admin` или другой?
   (Сам пароль — только в переменную в панели, мне его не говорите.)
4. **Имена и логины для жены и Сергея** — например `wife` / «Марина», `sergey` / «Мастер Сергей».
   Пароли им выдадите вы сами в разделе «Пользователи».
5. **Ветка для деплоя**: сливаем текущую рабочую ветку в `main` (рекомендую) или
   деплоим прямо из рабочей ветки?
6. **Для варианта A**: имя бакета S3 и регион/эндпоинт (их видно в панели после создания).
   Ключи — только в переменные приложения.
7. **Для варианта C**: IP-адрес созданного сервера (он не секретный) — чтобы я
   подготовил команды и инструкцию под него.
8. **Часовой пояс и рабочие часы** — подтвердите, что Москва и 09:00–19:00 верны.

Как только ответите на пункты 1–5, я доделаю код под выбранный вариант
(для A — выгрузку в S3), подготовлю ветку к слиянию в `main` и дам вам
короткий чек-лист «нажать здесь, вставить это» без лишних слов.

- [x] Секретов в репозитории нет, `.env` и `server/data/` в `.gitignore`
