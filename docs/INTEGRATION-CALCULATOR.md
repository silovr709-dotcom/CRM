# Интеграция: Калькулятор РЕцепт ↔ CRM

## Зачем

Калькулятор РЕцепт считает кухню (цены, материалы, замеры, КП). CRM ведёт
клиентов, сделки, график, оплаты, документы. Сейчас это два разных приложения
с разными данными. Цель: **расчёт из калькулятора становится сделкой в CRM**
с суммой, датами и файлом расчёта, а клиент в CRM видит свой заказ.

## Принципы

1. **CRM — источник правды по клиентам, сделкам, деньгам, графикам.**
   Калькулятор не дублирует клиентскую базу; он ссылается на клиента по имени/телефону.
2. **Калькулятор — источник правды по расчётам.** Себестоимость, материалы,
   замеры, КП живут только там; в CRM уходит только итог (сумма, даты, файл).
3. **Связь через общий идентификатор клиента** (телефон в цифрах) и
   **идентификатор проекта** (id проекта калькулятора).
4. **Offline-first:** оба приложения работают без сети; обмен — при появлении сети
   или вручную через файл/ссылку.

## Архитектура (3 фазы)

### Фаза 1 — Файловый мост (реализовано)
- Калькулятор: кнопка «Экспорт в CRM» → файл `*.crm.json` (bundle).
- CRM: кнопка «Импорт из калькулятора» в CRM → выбирает файл → создаёт сделку:
  - клиент ищется по имени/телефону, иначе создаётся;
  - сумма = цена для клиента из расчёта;
  - статус маппится (draft/sent/approved/archived → draft/offerSent/approved/delivered);
  - даты (замер/готовность/доставка/монтаж) → schedule сделки;
  - JSON расчёта прикрепляется как файл к сделке.
- Работает без сервера и без интернета (файл передаётся вручную).

### Фаза 2 — Общий сервер (следующий шаг)
- CRM-сервер (PHP) получает эндпоинты:
  - `POST /api/calc-project` — калькулятор пушит bundle при согласовании проекта;
  - `GET /api/calc-projects?client=...` — CRM тянет проекты клиента;
  - `GET /api/clients` — калькулятор тянет список клиентов CRM (чтобы не вводить повторно).
- Авторизация: общий токен (CRM-пользователь = калькулятор-пользователь).
- CRM при импорте проверяет `calculatorProjectId`: если проект уже импортирован —
  обновляет сумму/даты, а не создаёт дубль.

### Фаза 3 — Двусторонняя синхронизация
- Калькулятор и CRM используют один сервер (CRM-сервер) как хаб.
- Клиенты создаются в CRM, калькулятор читает их (поиск по телефону).
- Проекты калькулятора привязываются к dealId CRM; изменения в калькуляторе
  (новая цена, новые даты) пушатся в CRM и обновляют сделку.
- CRM показывает в сделке ссылку «Открыть расчёт в калькуляторе».

## Формат bundle (калькулятор → CRM)

```json
{
  "kind": "recept-calculator-project",
  "v": 1,
  "project": {
    "id": "project-id",
    "name": "Кухня на Ленина, 42",
    "client": "Иван Иванов",
    "phone": "+7 900 000-00-00",
    "address": "г. Тверь, ...",
    "date": "2026-05-01",
    "status": "approved",
    "pricebookName": "Висма 2026",
    "clientPrice": 123456,
    "cost": 98765,
    "measureAt": "2026-05-10",
    "deliveryAt": "2026-06-01",
    "installAt": "2026-06-05",
    "manager": "Менеджер"
  }
}
```

## Что уже реализовано

- Калькулятор: `exportToCrm(project, pricebook)` в `src/lib/exporters.ts`,
  кнопка «Экспорт в CRM» в редакторе проекта.
- CRM: `importCalculatorProject(bundle)` в `src/store.tsx`,
  кнопка «Импорт из калькулятора» в CRM (вкладка «Сделки»).
