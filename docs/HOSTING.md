# Свой домен и хостинг (reg.ru): подключение приложения

Приложение переезжает на **тверь-рецепт.рф** (в адресной строке браузера он же
`xn----ctbjba4ddbni5b6d.xn--p1ai`). На хостинге работает PHP-сервер приложения:
сотрудники входят по логину/паролю, роли проверяет сервер, общая база лежит
на вашем домене. GitHub Pages остаётся запасной копией статики.

Что уже сделано в коде:

- `server/api/index.php` — API: пользователи, вход по токену, роли
  (руководитель/менеджер/монтажник), общая база одним документом, версии.
  Деньги фильтруются по роли **на сервере**: монтажник не получает суммы,
  оплаты, план и затраты даже прямым запросом к API; менеджер — затраты.
- `server/.htaccess` — HTTPS-редирект, оболочка без кэша (телефон не будет
  «не видеть обновления»), хэшированные файлы — с долгим кэшем.
- `.github/workflows/deploy-hosting.yml` — автодеплой: сборка → тесты → FTP.
  Папку `api/data` на сервере деплой не трогает.

## Что нужно сделать вам в панелях (один раз, ~15 минут)

Пароли никуда в чат присылать не нужно: FTP-доступ вводится только в GitHub
и в панель reg.ru.

### 1. Привязать домен к хостингу и включить SSL

1. Панель reg.ru → «Хостинг» → ваш тариф «Хост-0» → убедитесь, что домен
   **тверь-рецепт.рф** добавлен к хостингу (если нет — «Добавить домен»).
2. Для домена включите бесплатный SSL: «SSL-сертификаты» → выпустить
   Let's Encrypt для тверь-рецепт.рф. Подождите выпуска (обычно до часа) —
   адрес должен открываться по `https://` без предупреждений.

### 2. Создать FTP-доступ для деплоя

1. Панель reg.ru → «Хостинг» → «FTP» → создать пользователя, например
   `deploy`, с доступом к папке домена (та, куда кладётся сайт — обычно
   `www/тверь-рецепт.рф/` или `public_html/`; посмотрите, где лежит текущий
   `index.html` домена).
2. Запомните: сервер FTP (обычно `ftp.<ваш-логин>.reg.ru` или IP из панели),
   логин, пароль и папку сайта (server-dir, со слешем в конце).

### 3. Добавить секреты в GitHub

Репозиторий CRM → **Settings → Secrets and variables → Actions → New
repository secret** — четыре секрета:

| Имя | Значение |
| --- | --- |
| `FTP_SERVER` | сервер FTP из панели reg.ru |
| `FTP_USERNAME` | логин FTP-пользователя `deploy` |
| `FTP_PASSWORD` | его пароль |
| `FTP_SERVER_DIR` | куда FTP кладёт файлы **от домашней папки FTP-пользователя**: если он стартует сразу из папки домена (видно в ISPmanager: вы сразу в папке сайта) — просто `./`; если из корня аккаунта — `www/xn----ctbjba4ddbni5b6d.xn--p1ai/` |

### 4. Запустить первую публикацию

GitHub → репозиторий CRM → **Actions → «Публикация на свой хостинг» →
Run workflow** (ветка `main`). Зелёный прогон = файлы на хостинге.
Дальше каждое обновление приложения публикуется само после слияния в `main`.

### 5. Первый вход

Откройте **https://тверь-рецепт.рф** — приложение встретит экраном
«Первый вход: создайте руководителя». Придумайте имя, логин (лучше латиницей)
и пароль от 6 символов. Затем в «Данных → Сотрудники на сервере» заведите
остальных: менеджеров и монтажников с их логинами и ролями.

Начинаем с чистой базы (так выбрано): демо-примеры можно выключить там же,
в «Данных». Текущий сайт на github.io продолжит работать как раньше —
его локальные данные на домен не переезжают.

## Как это работает дальше

- Вход по логину/паролю на любом устройстве; сессия — 30 дней.
- Изменения синхронизируются с сервером домена: при входе, каждые
  20 секунд и через секунду после правки. Чужая новая версия не затирается —
  при конфликте данные сливаются, а сервер хранит последние 12 версий
  (восстановить может руководитель через API/по запросу доработаем кнопку).
- Без интернета приложение продолжает работать локально и досинхронизируется,
  когда связь вернётся.
- Вложения (ведомости склада, файлы сделок) по-прежнему хранятся в браузере
  устройства, где их добавили; на сервер уходят записи и метаданные.

## Если что-то пошло не так

- **Открывается старый/пустой сайт**: проверьте, что `FTP_SERVER_DIR` —
  именно папка этого домена, и прогон Actions зелёный. Контроль доставки:
  откройте `https://<домен>/build.txt` — там дата и коммит последнего деплоя;
  если файла нет или дата старая, FTP кладёт файлы не в папку сайта.
- **В папке домена появилась вложенная папка `www`**: FTP-пользователь и так
  стартует из папки домена, а `FTP_SERVER_DIR` вида `www/<домен>/` создал
  копию сайта внутри сайта. Поставьте `FTP_SERVER_DIR` = `./` и запустите
  публикацию вручную ещё раз; лишнюю вложенную папку потом можно удалить.
- **`https` ругается на сертификат**: SSL ещё не выпустился — подождите и
  проверьте в панели reg.ru.
- **Приложение на домене не показывает вход, а работает как раньше**:
  папка `api/` не долетела — гляньте лог шага «Загрузка на хостинг по FTP».
- **Забыли пароль руководителя**: на сервере в файле `api/data/state.json`
  лежат только отпечатки паролей. Сбросить можно через панель хостинга:
  удалить `state.json` (база и пользователи пересоздадутся с нуля!) или
  попросите доработать сброс одной кнопкой.
