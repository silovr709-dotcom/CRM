# Запуск «МойДень» на своём домене (REG.RU) — пошагово

Документ для человека, который не программист. Делайте строго по шагам сверху вниз.
Всё вместе занимает **около часа**, из которых 40 минут — ожидание.

---

## 0. Результат аудита: что готово, а что нужно сделать

### ✅ Готово в коде, доделывать нечего

| Что проверял | Состояние |
|---|---|
| Вход по логину и паролю, у каждого свои данные | Работает, публичной регистрации нет |
| Защита сессии | Кука `httpOnly`, `SameSite=Lax`, при https — `Secure`, живёт 180 дней (телефон не разлогинивается) |
| Защита от подбора пароля | 10 попыток за 15 минут, дальше блокировка |
| Заголовки безопасности | CSP, nosniff, Referrer-Policy, HSTS на https |
| Работа за nginx | `trust proxy` включён, https определяется корректно |
| База | SQLite в режиме WAL, лежит в отдельной папке данных |
| Резервные копии | Автоматически раз в сутки + кнопка «Скачать копию» в разделе «Ещё» |
| Аккуратная остановка | По сигналу от системы база корректно закрывается, данные не бьются |
| Проверка состояния | `/api/health` — хостинг видит, что приложение живо |
| Приложение на телефоне | PWA: ставится на экран, обновляется само |
| Секреты | В коде и в GitHub паролей нет — они только в файле настроек на сервере |

### ❗ Что нужно решить до запуска

1. **Тариф «Хост-0» для этой системы не подойдёт.**
   «Хост-0» — это виртуальный хостинг для сайтов на PHP (WordPress, Битрикс).
   «МойДень» — это **постоянно работающая программа на Node.js 22** со своей базой.
   На виртуальном хостинге такое не запускается: там нет ни Node.js, ни права
   держать свою программу запущенной круглосуточно.
   **Нужен сервер:** в кабинете REG.RU это раздел **«Облачные серверы» (reg.cloud)**
   — от ~390–700 ₽/мес. Домен остаётся там же, где куплен, ничего переносить не надо.
   *Хост-0 можно не выбрасывать: см. раздел 10.*

2. **Перед установкой нужно влить изменения в `main`.**
   Весь свежий функционал (клиенты, деньги, платежи, поручения, доска заказов,
   аккаунты, выгрузка в Excel) лежит в Pull Request **#2**. Установщик берёт код из
   ветки `main`. Если не влить — на сервер уедет старая версия.
   Откройте https://github.com/silovr709-dotcom/CRM/pull/2 → зелёная кнопка
   **Merge pull request** → **Confirm merge**.

3. **В репозитории лежат ДВА разных приложения.**
   - `server/` + `web/` — «МойДень» (то, что мы развиваем: заказы, деньги, клиенты, задачи);
   - `crm-schedule/` — отдельное приложение «График монтажей» (склад, ведомости, PDF).
   Эта инструкция запускает **«МойДень»**. Если на домене должно работать второе —
   скажите, сделаю отдельно.

### 💡 Про «базу, которая меняется со всех устройств»

Ничего синхронизировать не нужно и никаких «копий на телефоне» не будет.
Схема такая:

```
   Ваш телефон  ┐
   Телефон жены ├──→  интернет  ──→  ваш сервер  ──→  ОДНА база данных
   Телефон Сергея┘                   (домен.ру)        /var/lib/myday
   Компьютер    ┘
```

Все открывают **один и тот же адрес**, у каждого свой логин. Жена вписала платёж —
вы видите это сразу, стоит обновить экран. Данные живут только на сервере, в одном файле,
который раз в сутки копируется автоматически.

## 1. Что купить (10 минут)

В личном кабинете REG.RU: **Облачные серверы** (reg.cloud) → **Создать сервер**.

| Параметр | Что выбрать |
|---|---|
| Операционная система | **Ubuntu 24.04** (можно 22.04) — чистая, без панелей |
| Тариф | **2 ГБ оперативной памяти**, 1–2 ядра, 20–30 ГБ диска |
| Регион | Москва |
| Резервные копии | Включить, если предлагают (+небольшая сумма, но это вторая страховка) |
| Доступ | Оставьте вход по паролю root — пароль придёт на почту |

> Минимальный тариф на 1 ГБ тоже заведётся — установщик сам добавит файл подкачки.
> Но 2 ГБ дают запас, и обновления будут проходить быстрее.

**Не нужны:** Docker-шаблоны, ISPmanager, FASTPANEL, MySQL, отдельная база данных.
Берите чистую Ubuntu — установщик поставит всё сам.

После создания запишите **IP-адрес сервера**, например `95.163.XXX.XXX`.

---

## 2. Направить домен на сервер (5 минут + ожидание)

Кабинет REG.RU → **Домены** → ваш домен → **DNS-серверы и управление зоной**.

Удалите существующие записи типа `A` для `@` и `www` (если они ведут на парковку или на Хост-0)
и добавьте две новые:

| Тип | Поддомен (subdomain) | Значение |
|---|---|---|
| A | `@` (или пусто) | IP вашего сервера |
| A | `www` | IP вашего сервера |

Сохраните. Обновление адресов по интернету занимает **от 15 минут до 2 часов**.
Пока ждёте — переходите к шагу 3, это не мешает.

---

## 3. Зайти на сервер (2 минуты)

Самый простой способ — **без установки программ**:
кабинет reg.cloud → ваш сервер → кнопка **«Консоль»** (VNC / веб-консоль).
Откроется чёрное окно. Введите:

```
login: root
password: (пароль из письма — при вводе он не отображается, это нормально)
```

> Кто умеет — может зайти через SSH: `ssh root@IP-адрес`. Результат тот же.

---

## 4. Установка — ОДНА команда (5–10 минут)

Скопируйте строку ниже, **замените `ВАШ-ДОМЕН.ру` и почту на свои**, вставьте в консоль
и нажмите Enter:

```bash
DOMAIN=ВАШ-ДОМЕН.ру EMAIL=ваша@почта.ру bash <(curl -fsSL https://raw.githubusercontent.com/silovr709-dotcom/CRM/main/deploy/install.sh)
```

*(в веб-консоли вставка обычно по правой кнопке мыши или Ctrl+Shift+V)*

> **Если команда не сработала** (бывает, что `raw.githubusercontent.com` недоступен
> из России) — используйте запасной вариант, он делает то же самое:
>
> ```bash
> apt-get update && apt-get install -y git
> git clone --depth=1 https://github.com/silovr709-dotcom/CRM.git /opt/myday
> DOMAIN=ВАШ-ДОМЕН.ру EMAIL=ваша@почта.ру bash /opt/myday/deploy/install.sh
> ```

Скрипт сам:
1. поставит Node.js 22, nginx и всё необходимое;
2. добавит файл подкачки, если памяти мало;
3. скачает код из GitHub и соберёт интерфейс;
4. заведёт отдельного пользователя и папку для данных `/var/lib/myday`;
5. придумает пароль администратора и сохранит его в файл;
6. настроит автозапуск (сервер перезагрузится — приложение поднимется само);
7. настроит nginx и закроет лишние порты;
8. выпустит **бесплатный SSL-сертификат** — сайт сразу заработает по `https://`.

В конце он напечатает адрес, логин и где лежит пароль. Если пароль потеряется:

```bash
cat /root/myday-admin.txt
```

> **Если сертификат не выпустился** — значит домен ещё не «доехал» (шаг 2).
> Подождите час и выполните на сервере:
> `certbot --nginx -d ВАШ-ДОМЕН.ру -d www.ВАШ-ДОМЕН.ру -m ваша@почта.ру --agree-tos --redirect`

---

## 5. Первый вход (3 минуты)

1. Откройте в браузере `https://ВАШ-ДОМЕН.ру`
2. Логин `admin`, пароль из `/root/myday-admin.txt`
3. Система сразу попросит **сменить пароль** — придумайте свой и запишите его в надёжное место.

---

## 6. Завести жену и Сергея (3 минуты)

**Ещё → Пользователи → + Пользователь**. Для каждого: имя, логин, временный пароль.
При первом входе человек сменит пароль сам.

Важно: **у каждого свои данные**. Общее — то, что вы друг другу **поручаете**
(задача «Поручить» уходит в список исполнителя, у вас остаётся во вкладке «Поручено мной»).

---

## 7. Поставить на телефоны (2 минуты на каждом)

- **Android (Chrome):** открыть `https://ВАШ-ДОМЕН.ру` → меню «⋮» → **«Установить приложение»**
- **iPhone (Safari):** открыть сайт → кнопка «Поделиться» → **«На экран «Домой»»**

Появится обычная иконка. Внутри — то же приложение, но без адресной строки.
Вход один раз — дальше телефон помнит (сессия живёт полгода).

---

## 8. Резервные копии — чтобы не потерять данные

Что уже работает само:
- раз в сутки сервер делает копию базы в `/var/lib/myday/backups` (хранится 14 последних);
- перед каждым обновлением создаётся отдельная копия.

Что стоит делать руками **раз в месяц** (2 минуты):
**Ещё → Мой аккаунт → «Скачать копию»** — файл `.db` сохранится на компьютер.
Это ваша страховка на случай, если с сервером случится беда.

Дополнительно советую включить **снимки сервера (бэкапы)** в панели reg.cloud —
тогда весь сервер можно откатить на вчера одной кнопкой.

---

## 9. Обновление до новой версии

Когда в GitHub появятся улучшения, зайдите в консоль сервера и выполните:

```bash
bash /opt/myday/deploy/update.sh
```

Скрипт сделает копию базы, скачает новую версию, пересоберёт интерфейс и перезапустит
приложение. **Данные не трогаются.** На телефоне достаточно закрыть и открыть приложение.

## 10. Что делать с тарифом «Хост-0»

Варианты, от лучшего к худшему:

1. **Вернуть деньги / обменять.** Если с покупки прошло мало времени, напишите в поддержку
   REG.RU: «тариф не подходит, прошу перенести средства на облачный сервер reg.cloud».
   Обычно идут навстречу, особенно в первые 14 дней (тестовый период).
2. **Оставить под почту на домене** — `почта@ваш-домен.ру` выглядит солиднее, чем gmail,
   и для почты виртуальный хостинг подходит.
3. **Оставить под сайт-визитку** на поддомене, например `www.ваш-домен.ру` — но тогда
   на шаге 2 запись `www` ведите на Хост-0, а не на сервер.

## 11. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| Сайт не открывается по домену | Домен ещё не «доехал». Проверьте по IP: `http://IP-адрес` — если работает, просто подождите |
| «Небезопасное соединение» | Сертификат не выпущен — команда из конца шага 4 |
| Страница белая / ошибка 502 | `systemctl status myday` и `journalctl -u myday -n 50` — покажут причину |
| Забыл пароль администратора | `cat /root/myday-admin.txt`; если файла нет — заведите новый пароль через поддержку этого проекта |
| Нужно перезапустить | `systemctl restart myday` |
| Хочу посмотреть, сколько места занято | `df -h` и `du -sh /var/lib/myday` |
