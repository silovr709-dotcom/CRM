# Архитектура — CRM и График монтажей

## Принципы

1. **Local-first.** Приложение всегда работает с локальной копией данных
   (localStorage + IndexedDB для файлов) и не блокируется сетью.
2. **Один серверный файл.** Весь бэкенд — `server/api/index.php`: без
   фреймворков и базы данных, состояние — один JSON-файл под flock.
   Это осознанный выбор под shared-хостинг с PHP.
3. **Доступ проверяется на сервере.** Роли (руководитель, менеджер,
   монтажник) фильтруют деньги и настройки в PHP, а не только в интерфейсе.
4. **Удаления — с «надгробиями».** Синхронизация хранит списки удалённых
   записей (клиенты, сделки, приходы, события) с TTL, чтобы удаление
   доехало до всех устройств и не воскресало из старых копий.

## Стек

| Слой | Технология |
|---|---|
| Frontend | React 19 + TypeScript + Vite, PWA (service worker `crm-v7`) |
| Backend | PHP 8, один файл `server/api/index.php`, состояние `api/data/state.json` |
| Файлы вложений | blob'ы `api/data/files/<id>.bin`, метаданные в состоянии |
| Деплой | GitHub Actions → FTP (reg.ru), маркер `build.txt` |
| Тесты | Vitest, 39+ файлов по библиотекам `src/lib` |

## Данные

`AppData` — единый документ: клиенты, сделки (с задачами, оплатами,
графиком), складские приходы, свободные события графика, настройки.
Нормализация при чтении (`src/lib/storage.ts`) приводит любой вход
к валидной форме; неизвестные поля отбрасываются.

## Синхронизация

- **Серверный режим** (свой домен): `GET/POST ?action=data`, ревизия
  документа, последние 12 версий с восстановлением (только руководитель).
  Файлы вложений — отдельными запросами (`files`, `file`,
  `file_upload`, `file_delete`), локальный кэш — IndexedDB.
- **Локальный режим** (GitHub Pages): данные только в браузере; по желанию —
  общая база через Supabase (код доступа, таблица-документ).

## Безопасность

- Пароли — `password_hash`; сессии — SHA-256 от токена, TTL 30 дней.
- Троттлинг входа: 5 неудачных попыток → пауза 15 минут по IP и логину.
- Лимиты: тело запроса 8 МБ, файл вложения 10 МБ.
- Монтажник не получает суммы сделок с сервера; менеджер — без расходов.

## Напоминания

`src/lib/reminders.ts` — чистый движок: из базы и правил строит моменты
(задачи, монтажи, доставки, готовность, дни рождения, свободные события),
сравнивает с уже отправленными и отложенными.

Офлайн-доставка — тремя путями, интернет не нужен ни одному:
1. При открытом приложении — уведомления браузера/PWA (`src/lib/notify.ts`).
2. Расписание устройства (`src/lib/localReminders.ts`): ближайшие
   напоминания заранее ставятся в системное расписание (Notification
   Triggers), и система показывает их в срок даже при закрытом приложении.
   Где браузер так не умеет (iPhone), этот путь честно отключается.
3. Календарь телефона (`src/lib/reminderCalendar.ts`): экспорт напоминаний
   на 90 дней в .ics с будильниками VALARM — телефон напоминает сам.

Service worker при установке предкэширует всю сборку по манифесту Vite,
поэтому приложение целиком работает без сети с первого запуска.
