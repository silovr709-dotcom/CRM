# Архитектура — Персональный AI-органайзер

## Принципы

1. **Универсальная сущность — ЗАДАЧА.** Событие, поездка, покупка, доставка, звонок,
   напоминание — это типы задачи, а не отдельные подсистемы. Рабочие и личные дела
   живут в одном календаре, различаясь категориями.
2. **Бизнес-логика отделена от интерфейса.** Всё, что происходит при изменении задачи
   (автоматизации, повторения, зависимости, история), выполняется на сервере в
   сервисном слое — независимо от того, с какого экрана пришло изменение.
3. **AI предлагает — пользователь подтверждает.** Любой план, разбор фразы или команда
   сначала возвращаются как «предложение» (proposal) и применяются только после
   подтверждения.

## Стек

| Слой      | Технология                                       |
|-----------|--------------------------------------------------|
| Backend   | Node.js 22+, Express, `node:sqlite` (встроенный)  |
| БД        | SQLite, файл `server/data/organizer.db` (в .gitignore) |
| Frontend  | React 18 + TypeScript + Vite, без тяжёлых UI-библиотек |
| Ассистент | Встроенный NL-парсер и правила (RU). Нейросети и внешние API не используются |
| Аккаунты  | Логин/пароль (scrypt), сессии в БД, httpOnly-cookie `myday_sid` (30 дней) |
| Облако    | Docker (`Dockerfile`); постоянный том `/data` либо снимки базы в S3 |

## Структура репозитория

```
server/
  src/
    index.js            — Express, маршруты
    db.js               — схема БД, миграции, сид данных
    util/dates.js       — даты, рабочие дни, слоты времени
    services/
      activity.js       — журнал истории (activity_log)
      tasks.js          — CRUD задач + хуки жизненного цикла
      recurrence.js     — повторяющиеся задачи
      automations.js    — движок автоматизаций (КОГДА → ТОГДА)
      templates.js      — шаблоны → генерация цепочек задач
      planner.js        — «Распланировать день», «Разгрузить день», свободные окна
      today.js          — сборка экрана «Сегодня» / брифинг / вечерний разбор
      nl/parser.js      — разбор естественного языка → план действий
      nl/commands.js    — команды («перенеси на пятницу», «удали», …)
      nl/assistant.js   — AI-диалог: ответы на вопросы по реальным данным
      nl/quick.js       — умная строка: «завтра в 10:00 замер у Петровых» → задача
      users.js          — пользователи, пароли, сессии
      backup.js         — локальные резервные копии базы (VACUUM INTO)
      s3.js             — клиент S3 (подпись AWS SigV4 на node:crypto)
      s3restore.js      — восстановление базы из S3 при старте контейнера
      persist.js        — снимки базы в S3 и выгрузка/загрузка вложений
    paths.js            — пути к данным (DATA_DIR), известны до открытия базы
    ctx.js              — AsyncLocalStorage: текущий пользователь (runAs/uid)
    routes/*.js         — тонкие HTTP-обработчики
web/                    — SPA (React + TS)
  src/
    api.ts, types.ts
    pages/  (Today, Calendar, Tasks, Projects, ProjectView, Notes, More…)
    components/ (TaskModal, AiModal, QuickAdd, Timeline, …)
```

## Модель данных (SQLite)

- `tasks` — универсальная задача: `type` (task/event/trip/purchase/delivery/work/
  personal/call/meeting/reminder/…), `status` (inbox/planned/in_progress/done/
  cancelled/paused), `schedule_mode` (**fixed / flexible / deadline**), дата, время,
  длительность, дедлайн, приоритет, проект, категория, контакт, место (откуда/куда),
  `parent_id` (подзадачи), `recurrence` (JSON-правило), `extra` (JSON: груз, водитель…).
- `task_dependencies` — зависимости (`after`, `with`, `requires`).
- `projects` — статус, дедлайн, пауза (`pause_until`), прогресс считается по задачам,
  «следующее действие» вычисляется (ближайшая незаблокированная задача).
- `notes` — заметки, привязываются к проекту/задаче/контакту; «быстрая заметка» —
  просто заметка без привязок.
- `reminders` — напоминания (по времени, до/после события, к задаче/заметке).
- `categories`, `contacts`, `locations` — справочники (категории — пользовательские).
- `templates` + `template_steps` — шаблоны цепочек (Доставка, Монтаж, Новый клиент,
  ТО автомобиля…): смещения в днях/рабочих днях, зависимость от предыдущего шага.
- `automations` — правила: триггер (`task_completed`…) + условия (тип/категория/
  проект/текст) + действие (создать задачу через N (рабочих) дней, создать напоминание).
- `activity_log` — история: создано / изменено / перенесено / выполнено / отменено /
  пауза / возобновлено.
- `settings` — key/value по умолчанию (рабочие часы, буфер планирования, резерв дня).
- `users` / `sessions` / `user_settings` — аккаунты, долгие сессии (30 дней) и
  персональные настройки (включая свой Telegram-токен у каждого).
- Многопользовательность: у всех пользовательских таблиц есть `user_id`, сервисы
  подставляют его из `ctx.js` (AsyncLocalStorage), поэтому данные не пересекаются.
- Деньги и конвейер: у `projects` — `price`, `prepaid`, `stage` (Замер → … → Сдано),
  `contact_id` (клиент). Долг = `price - prepaid`.

## Поток жизненного цикла задачи

```
Задача завершена (любой экран)
  → services/tasks.completeTask()
      → activity_log («выполнено»)
      → recurrence: создать следующее повторение
      → automations: подобрать правила → создать задачи/напоминания (+N рабочих дней)
      → dependencies: разблокировать зависимые задачи
      → project: пересчитать прогресс / следующее действие
```

## AI-слой

Все AI-функции работают через единый эндпоинт `POST /api/assistant`:

1. **Разбор фразы** («завтра утром съездить на склад, забрать фасады, потом отвезти
   их на объект…») → `parser.js` делит фразу на действия, определяет тип, дату,
   время, длительность и зависимости → возвращает **план-предложение**.
   Применение — только после `POST /api/assistant/confirm`.
2. **Команды** («перенеси на пятницу», «напомни через неделю», «удали») →
   `commands.js`, тоже через подтверждение.
3. **Вопросы** («что у меня сегодня?», «что просрочено?», «что я забыл?») →
   `assistant.js` отвечает только на основании данных БД.
4. **Планирование** — `planner.js`: жёсткие задачи (fixed) образуют каркас,
   гибкие раскладываются по свободным окнам с буфером, день не забивается на 100%.

Внешние нейросети **не используются**: весь разбор и все ответы строятся на
правилах и данных БД. Это осознанное решение — работает офлайн, бесплатно,
данные никуда не уходят.

## Интеграции (архитектура, без фиктивных реализаций)

Таблица `integrations` и слой `notifications` спроектированы так, что доставка
уведомлений — это провайдер с интерфейсом `send(reminder)`. В текущей среде работает
внутренний провайдер (in-app). Push / Apple Calendar / Apple Reminders / email /
Telegram подключаются как дополнительные провайдеры без изменения бизнес-логики.

## Что реализовано в первой версии (MVP)

Сегодня (сейчас/далее/таймлайн/требует внимания/свободное время), календарь
(день/3 дня/неделя/месяц/список), задачи (типы, статусы, приоритеты, дедлайны,
fixed/flexible/deadline, подзадачи, зависимости, повторения), проекты (прогресс,
следующее действие, пауза), заметки (+быстрые), напоминания, шаблоны, автоматизации,
история, AI-ввод, AI-диалог, команды, «Распланировать день», «Разгрузить день»,
«Что я забыл», утренний брифинг и вечерний разбор, мобильная версия (нижняя
навигация + большая кнопка «+»).


## Развёртывание

Один контейнер содержит собранный фронтенд, API и Telegram-бот (long polling,
отдельный цикл на каждого пользователя с токеном). Изменяемые данные — только в
`DATA_DIR` (`/data` в облаке): `organizer.db` и папка `files/`.

Точка входа — `src/index.js`: до открытия SQLite он вызывает `restoreIfNeeded()`
и, если площадка не даёт постоянного диска (Timeweb App Platform), скачивает
последний снимок базы из S3. Дальше `app.js` поднимает сервер, `persist.js`
выгружает снимки каждые `SNAPSHOT_EVERY_MIN` минут и обязательно по SIGTERM.
Все операции с S3 «мягкие»: при недоступности хранилища приложение продолжает
работать на локальном диске и пишет ошибку в лог и в `/api/admin/storage`.
