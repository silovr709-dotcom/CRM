# Публикация сайта и обновления без новых сессий

Короткая инструкция: что нажать на GitHub один раз и как дальше попадают изменения.

## 1. Что уже сделано в репозитории

- `.github/workflows/crm-schedule.yml` — сборка, тесты и публикация:
  - **pull request** → только проверки (`npm ci`, `npm test`, `npm run build`);
  - **push в `main`** → те же проверки и деплой `crm-schedule/dist` на Pages;
  - **workflow_dispatch** → кнопка «Run workflow» для ручного запуска.
- Приложение собрано с `base: './'`, поэтому работает из подпапки `/CRM/`:
  ассеты, иконки, манифест и service worker берут относительные пути.
- Ветка сессии `arena/076e528a-crm` слита в `main` (PR #3), `crm-schedule/` уже в `main`.

## 2. Что нужно нажать на GitHub (один раз)

1. **Settings → Pages → Build and deployment → Source: `GitHub Actions`.**
   Сейчас там стоит «Deploy from a branch» (ветка `main`, корень) — в этом режиме
   Pages собирает корень репозитория, а приложение лежит в `crm-schedule/`, поэтому
   сайт его не показывает.
2. **Actions → «CRM + График монтажей» → Run workflow** → ветка `main` → **Run workflow**.
   Через 1–2 минуты сайт открывается: `https://silovr709-dotcom.github.io/CRM/`.
3. (необязательно) **Settings → General → Pull requests → Allow auto-merge** —
   чтобы правки уезжали в `main` без ручных действий.
4. (необязательно) **Settings → Pages → Custom domain** — свой домен;
   HTTPS-сертификат выдаётся автоматически, включите «Enforce HTTPS».

Проверить, что деплой прошёл: **Actions → «CRM + График монтажей»** — зелёная
галочка у запуска, внутри job «Публикация» есть ссылка на сайт.

## 3. Как выглядят дальнейшие правки

1. Вы пишете в чат, что поменять.
2. Агент правит код в ветке сессии `arena/076e528a-crm`, гоняет `tsc`, тесты и сборку.
3. Коммит уходит в `arena/076e528a-crm`, оттуда открывается (или обновляется) PR в `main`.
4. PR сливается в `main` → workflow сам пересобирает и публикует сайт.
5. Через ~1 минуту изменения уже на `https://silovr709-dotcom.github.io/CRM/`.

Новая сессия чата **не нужна**: работа идёт в той же ветке, а так как каждый круг
сливается в `main`, даже новая сессия начнётся с актуального состояния — ничего
не потеряется.

## 4. Что стоит помнить

- **Данные не на сервере.** Сайт — это оболочка приложения; сделки, клиенты и файлы
  лежат в браузере (localStorage + IndexedDB). У каждого устройства своя база,
  перенос — через копию `.json`/`.zip` в разделе «Данные».
- **Репозиторий публичный**, значит сайт тоже публичный: открыть может любой, кто
  знает адрес, но данных там нет — только код. Приватный Pages требует платного
  плана GitHub.
- **Обновления и кэш.** Service worker обновляет оболочку при заходе; когда вышла
  новая версия, появляется тост «Доступна новая версия» с кнопкой «Обновить».
  Если что-то выглядит по-старому — `Ctrl+Shift+R` или закройте и откройте вкладку.
- **Установка на телефон**: открыть сайт → «Поделиться» → «На экран „Домой“»
  (iPhone) или меню браузера → «Установить приложение» (Android).
- **Сломанная сборка не попадёт на сайт**: деплой идёт только после зелёных тестов.
